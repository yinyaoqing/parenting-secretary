## 給審閱 AI 的說明

這份文件是一款育兒 APP 的規劃，請你以批判性審閱者的身分提出具體改進建議。本文件會依序交給多個 AI 審閱，每輪回饋會整合進下一版。

**本產品的五項開發原則（第四輪起生效，審閱時必須以此為前提）**

1. 無任何顧問。所有建議不得踩法規紅線，且必須附明確、可公開查核的資料來源；沒有來源的內容一律不進產品。
2. 第一階段即完成 0–3 歲全部功能，不再切成 0–12 個月 MVP。
3. 長期目標是 18 歲前所有育兒資訊需求：後續會加入課表、補習班提醒、慢性病服藥提醒、依發展需求建議活動（如律動課）、運動傷害後的舒緩運動等。架構必須從現在就能承載。
4. 一個人搭配 AI 開發，以最小成本規劃時程。
5. 教養與照顧風格（常見稱呼如「百歲」「親密育兒」）由主要照顧者透過問卷或選擇決定，APP 依方向提供建議，但不得覆寫安全層。

**審閱角色**：請依序切換以下視角檢視，每個視角至少提出一項具體意見。

| 視角 | 審閱重點 |
|---|---|
| 兒科醫師 | 安全層是否完整、每個數值是否有可查核來源、是否誤入診斷或分級 |
| 發展心理與臨床心理師 | 風格問卷的向度是否合理、證據標籤是否公允 |
| 精神動力與客體關係學者 | 理論白話翻譯是否準確 |
| 營養師 | 副食品、過敏原、噎食、乳品數值與來源 |
| 產品經理 | 一人開發的範圍、18 歲架構、定價 |
| UX 設計師 | 風格問卷流程、單手夜間操作、長輩可用性 |
| 行動工程師 | 無後端架構、本地通知可靠性、備份與還原 |
| 資料科學家 | 規則式提醒與安全網的簡化是否仍正確 |
| 台灣法規顧問 | 紅線自檢表是否遺漏、內容授權分級是否正確 |
| 主要照顧者（使用者） | 風格選擇是否造成罪惡感、哪些內容真的會看 |

**審閱原則**

- 優先指出錯誤、風險與遺漏，不需要稱讚。
- 涉及醫療、營養、法規的數值或主張，請附來源與查核日期；沒有來源的建議請直接標示「無來源，不建議採用」。
- 本版有兩張關鍵表：「紅線自檢表」與「數值來源表」。請優先攻擊這兩張表的遺漏。
- 若你看到前一輪意見（「審閱紀錄」），請表示贊同、反對或補充。

## 1. 產品概述

**一句話定位**：懂孩子、也懂照顧者的育兒秘書。

**法規定位**：紀錄、衛教連結、提醒、導向政府既有服務。不做任何疾病診斷、監測、分級判讀，不生成醫療內容。

**目標使用者**：0–3 歲孩子的主要照顧者；長期為 0–18 歲孩子的家庭。

### 1.1 市場現實（更新）

| 項目 | 數字 | 來源與查核日期 |
|---|---|---|
| 2025 年出生數 | 107,812 人，年減 20% | 中央社 2026-01-09；查核 2026-10-05 |
| 2024 年出生數 | 134,856 人 | 同上 |
| 三年世代家庭數 | 約 35 萬 | 以 2025 年出生數估算 |
| 0–18 歲總人口 | 以每年 10.8 至 20 萬出生估算約 300 萬人 | 內政部人口統計（上線前查核） |
| 產後護理之家入住 | 2019 年 111,033 人次，約六成產婦；台北市 67% | 消基會；查核 2026-10-05 |
| 一人開發固定成本 | 每年約 NT$4,000（見 7.3） | Apple、Google、Expo 官方定價 |

**結論**：v0.3 說「養不起顧問團」，但本產品沒有顧問團。以一人開發、年固定成本低於 NT$5,000 計，台灣市場即使只有數千付費家庭也能損益兩平。真正的風險不是市場大小，而是（a）無顧問下的內容正確性與法規風險，（b）一人能否維護 18 年份的內容更新。本版的設計全部圍繞這兩點。

### 1.2 核心差異化（依優先序）

1. **照顧風格導向的內容**：問卷決定方向，同一主題依風格給不同的做法順序，安全層不變。
2. **只引用可查核來源的內容**：每張卡片附官方來源連結與查核日期，使用者可以自己點開驗證。競品多為原創內容，無法驗證。
3. **台灣公費資源時程一站整合**：9 次兒童預防保健、6 次兒童發展篩檢、塗氟、疫苗、新生兒篩檢、維生素 D、乘車安全。
4. **照顧者支持**：狀態打卡與資源導向，不計分篩檢。
5. **資料完全在使用者手上**：無帳號、無伺服器；備份在使用者自己的雲端硬碟。

### 1.3 階段價值

| 階段 | 核心價值 | 主力模組 |
|---|---|---|
| 0–12 個月 | 紀錄、安全、照顧者支撐 | 快速紀錄、安全網提醒、固定安全層、照顧者支持、副食品、公費資源時程 |
| 12–36 個月 | 理解孩子、行為引導、自主發展 | 發展篩檢準備、風格化行為引導、如廁訓練、挑食、情緒教練 |
| 3–18 歲（後續內容包） | 學習生活、健康維護、心理健康 | 行程、服藥提醒、年齡段內容包、公費資源時程延伸 |

**早產兒矯正月齡**：建檔時詢問預產期與實際出生日，2 歲前的發展內容以矯正月齡呈現，疫苗依實際月齡，介面同時顯示兩者（來源：國健署孕產兒關懷網站早產兒專區，上線前查核確切文字）。

### 3.1 內容授權三級制

### 3.2 每張內容卡的必備欄位

### 3.3 更新機制（一人可維護）

- 每季執行一次腳本：檢查所有來源 URL 是否存活、頁面內容雜湊是否改變；改變者列入待複查清單。

- 使用者端顯示「此內容查核日期」，超過 12 個月自動加註「請以官方網站為準」。

## 4. 功能模組（第一階段全部完成 0–36 個月）

### 4.1 建檔與照顧風格問卷（新增）

**建檔**：孩子姓名或暱稱、出生日、預產期（早產兒）、餵養方式、目前所在（家中／產後護理之家，若在機構則輸入預定出所日，內容與提醒從出所日開始）。

**照顧風格問卷**：六個向度，每向度 1–2 題，約 90 秒完成，隨時可改。

| 向度 | 兩端 | 影響的功能 |
|---|---|---|
| 作息結構 | 固定時間表 ↔ 跟隨孩子訊號 | 提醒預設模式（排程提醒 vs 安全網提醒）、一日作息範本是否顯示 |
| 哭聲回應 | 立即回應 ↔ 先觀察再回應 | 安撫方法排序、睡眠方法排序 |
| 睡眠安排 | 獨立房間 ↔ 同房不同床 ↔ 同床（顯示國健署不建議同床的固定文字） | 睡眠內容排序；安全層不變 |
| 餵食主導 | 大人安排 ↔ 孩子主導 | 副食品取向排序（泥狀 vs BLW）、挑食做法排序 |
| 行為引導 | 規則與後果 ↔ 情緒先行 | 12–36 個月行為卡排序 |
| 資訊量 | 只要做法 ↔ 想看理論 | 是否預設展開第三層理論 |

**三個預設**（以向度命名，不用書名；「常見稱呼」只在說明文字出現）：

- **結構型**：固定作息、先觀察再回應、獨立睡眠、大人安排餵食。常見稱呼：規律作息派、百歲派。
- **回應型**：跟隨訊號、立即回應、同房、孩子主導。常見稱呼：親密育兒、回應式照顧。
- **混合型**：白天跟隨訊號、夜間固定流程。

**風格層不得覆寫安全層**（R7）。具體規則：

- 任何風格下，安全睡眠內容、發燒固定文字、噎食清單、蜂蜜與果汁限制都照常顯示且不可關閉。
- 結構型在 0–6 個月：餵食提醒仍以「安全網」為預設，並顯示國健署「新生兒依需求哺餵、每天約 8–12 次」的文字；一日作息範本標示為「參考，不是目標」。
- 行為式睡眠訓練（逐步撤離、定時安撫）內容在 6 個月前不呈現為可選做法，說明其證據來自 6 個月以上的研究（Gradisar 2016、Price 2012）。
- 若使用者選「同床」，顯示國健署同房不同床的固定文字，並列出降低風險的官方建議連結，不阻擋使用者繼續。
- 問卷結果頁明示：「這是你的偏好，不是評分；沒有一種風格對所有孩子都對。」

### 4.2 快速紀錄

目標：單手、三秒內完成一筆。

| 類別 | 紀錄內容 |
|---|---|
| 飲食 | 母乳（左右側、時長、親餵或瓶餵）、擠奶量與母乳庫存（附儲存期限提示，數值見 3.4）、配方奶／鮮奶 ml、副食品、新食材、食物接受度、餵食開始原因（訊號／提醒／排程） |
| 尿布／如廁 | 濕／便／兩者、便便顏色（連結國健署嬰兒大便卡頁面）、如廁嘗試 |
| 睡眠 | 小睡與夜間睡眠起迄、夜醒、入睡方式 |
| 新生兒觀察 | 臍帶護理、體重回升、清醒趴臥時間、哭鬧時段、出院後黃疸回診提醒（不做照片） |
| 生長 | 身高、體重、頭圍，顯示 WHO 生長曲線百分位（與兒童健康手冊相同的呈現） |
| 健康 | 體溫（必填量測部位，顯示該部位的發燒定義，不產生判斷）、症狀、用藥（使用者自行輸入藥名與醫囑間隔）、就醫 |
| 情緒行為日記 | 情緒爆發、分離焦慮、新技能、有趣的話 |

**用語規範**：禁用「趴睡」，一律「清醒趴臥時間」；「噎食」不寫「噪食」。

**輸入方式（第一階段）**：首頁大按鈕、桌面小工具（Expo 支援度有限，列為可選）、夜間低亮度模式、事後補登、無障礙（VoiceOver／TalkBack、動態字級）。穿戴、語音助理、動態島不做。

**暫停模式**：一鍵暫停全部提醒與內容推送，用於住院、喪慟、暫時交由機構照顧；設定第一層；不詢問原因。

### 4.3 提醒引擎（規則式，無機器學習）

一人開發下，v0.3 的共軛模型簡化為可解釋的規則，數學見第 6 章。

- **安全網提醒**（所有風格預設）：距上次餵食或換尿布超過個人近期間隔的上界時提醒；文案「距上次餵奶已較久，寶寶醒著嗎？有沒有找奶的樣子？」
- **排程提醒**（結構型或使用者開啟）：使用者設定間隔或時刻表，APP 不自動調整。
- **用藥提醒**：使用者輸入醫囑間隔與次數，APP 只倒數，不建議劑量（R6）。
- **公費資源與疫苗提醒**：依 JSON 時程表與孩子出生日計算。
- **行程提醒**（通用，為 18 歲架構預留）：週期性事件，如課表、補習班、復健。
- 孩子睡覺時不發送非必要提醒；提醒連續被忽略時降低頻率並詢問是否關閉。

### 4.4 發展篩檢準備工具

- 錨點：國健署 6 次兒童發展篩檢（2024-07-01 起）與 9 次兒童預防保健（2026-07-01 起）。
- 功能：時程提醒、「發展觀察日記」（觀察句、不計分、不產生風險等級）、「這次篩檢想問醫師的事」清單。
- 月齡內容：每週（0–3 個月）或每月一張「這個時期的孩子」卡，內容只取 A 級來源的文字並附連結。
- 里程碑語意統一採 CDC 2022 修訂版「大多數孩子（75%）在此月齡已做到」。
- 紅旗：只呈現國健署頁面明列的「建議提早諮詢」情形，附原文連結，不用「疑似」。
- 不內嵌 M-CHAT-R（R2；PPV 見 3.4）。

### 4.5 飲食模組

- 副食品開始：依 3.4 數值；準備度檢核僅供與醫師討論。
- 泥狀餵食與 BLW 並列；依風格決定先顯示哪一種；噎食與作嘔的區分、噎食急救以連結國健署或消防署官方影片呈現（B 級）。
- 過敏原：不刻意延後引入，高風險寶寶先諮詢醫師（來源：國健署孕產兒關懷網站，上線前查核）；全身性過敏反應的 119 固定文字（引用國健署或衛福部頁面，上線前查核）。
- 1 歲轉換：乳品量依 3.4；用杯子、戒奶瓶；1 歲前不喝果汁；6 個月前不另給水。
- 母乳延續與離乳：WHO 建議哺餵至 2 歲或更久；APP 不催促斷奶。
- 噎食安全清單依 3.4。
- 挑食：食物恐新症時間窗依 3.4；重複接觸次數計算；「大人決定提供什麼、何時、在哪裡；孩子決定吃不吃、吃多少」以自寫白話描述，註明概念出自 Ellyn Satter，不逐字重製（R2）。
- 行為引導內容（挑食、戒奶瓶）只在使用者開啟該模組時出現，不主動推送。

### 4.6 睡眠模組

- 依月齡顯示總睡眠時數參考與清醒時間窗（來源：國健署或 AASM 2016 兒童睡眠時數共識，上線前擇一並查核）。
- 睡眠方法依風格排序：回應型先顯示陪睡、漸進陪伴；結構型先顯示固定流程、逐步撤離（6 個月以上才顯示為可選）。每個方法附證據標籤與來源。
- 安全睡眠為固定層，不受風格影響。

### 4.7 如廁訓練

- 準備度檢核（來源：國健署或 AAP HealthyChildren，上線前查核）。
- 漸進式、孩子主導式、密集式並列，依風格排序。

### 4.8 官方內容檢索（取代 AI 秘書）

- 離線關鍵字與同義詞搜尋，資料庫只含 A 級來源的段落與 B 級來源的標題連結。
- 回傳原文段落、來源、查核日期；不生成、不改寫、不回答「要不要就醫」。
- 搜尋含「發燒」「呼吸」「抽搐」「誤食」「不醒」等詞時，結果最上方固定顯示 119 與就醫文字（固定文案，非判斷）。

### 4.9 照顧者支持

- 每日 10 秒狀態打卡（睡眠、精力、情緒）；連續低落時顯示資源，不計分。
- 常駐「想聊聊嗎」入口：國健署孕產婦關懷專線 0800-870-870、1925 安心專線、各縣市社區心理衛生中心、孕產婦心理健康服務頁面連結。產後 2 週與 6 週各一次性邀請。
- 不內嵌 EPDS（R2）。
- 「請求支援」：由本人選擇收件人並預覽文字，透過系統分享（簡訊、LINE 等）送出；APP 本身不需伺服器。
- 哭鬧高峰與受虐性頭部創傷預防：引用國健署文字並附連結。
- 理論基礎（第三層）：Winnicott「夠好的照顧者」、Tronick 修復概念、Bion 容器概念。

### 4.10 分享與報表（無伺服器版）

- 第一階段無多裝置即時同步。替代：匯出 JSON 與 CSV、匯出 72 小時照護紀錄 PDF（只呈現紀錄）、以系統分享傳給家人。
- 備份與還原：匯出加密 JSON 到使用者自己的 iCloud Drive 或 Google Drive（經系統檔案選取器），APP 不接觸雲端帳號。
- 第二階段再評估家庭同步（需伺服器與帳號，法規與成本同時上升）。

### 4.11 公費資源時程

以 JSON 時程表驅動，所有項目附來源與查核日期（見 3.4）：9 次兒童預防保健、6 次兒童發展篩檢、塗氟、公費疫苗、新生兒篩檢、維生素 D、乘車安全。APP 導向健保快易通健康存摺查詢疫苗紀錄，不重做資料庫。

### 4.12 行程模組（為 18 歲預留，第一階段只做骨架）

- 週期性事件：名稱、星期與時間、地點、提醒提前量、備註。
- 第一階段用途：托嬰、親子館、復健、回診。
- 後續用途：課表、補習班、才藝、服藥（醫囑由使用者輸入）。
- 可選同步到裝置行事曆（Expo Calendar），避免自建提醒的可靠性問題。

## 5. 安全層（固定文字，不可關閉，不受風格影響）

每一條都引用 A 級來源原文並附連結；B 級來源只放連結。

- **安全睡眠**：仰睡、堅硬平坦床面、不放枕頭被子玩偶、同房不同床、不趴睡不側睡。清醒趴臥時間只在清醒且有人看著時進行。（國健署）
- **發燒**：各部位定義見 3.4。3 個月以下發燒立即就醫；耳溫不適用 3 個月以下；腋溫不可用於排除發燒；未經醫師指示不自行給退燒藥。（台灣兒科醫學會）APP 只顯示讀數與定義，不判斷。
- **低體溫**：見 3.4（WHO）。
- **新生兒進食與尿布**：濕尿布參考數見 3.4；嗜睡叫不醒、長時間未進食、膽汁色嘔吐等以國健署頁面原文呈現。APP 顯示計數，不警示。
- **噎食**：清單見 3.4；急救以官方影片連結呈現。
- **1 歲前不吃蜂蜜；1 歲前鮮奶不作為主要飲品；1 歲前不喝果汁；6 個月前不另給水。**
- **受虐性頭部創傷預防**：哭鬧高峰與「安全放下、離開幾分鐘」。（國健署）
- **乘車安全**：2 歲以下後座後向式。（交通部法規）
- **全身性過敏反應、呼吸困難、抽搐、誤食**：固定 119 文字。

## 6. 提醒數學（簡化為一人可實作的規則）

### 6.1 安全網上界

- 取最近 N 筆（預設 20 筆，不足時併入月齡常模的虛擬樣本）自發事件的間隔，排除標記為「提醒引發」的事件。
- 上界 = 這些間隔的第 90 百分位，與該月齡的安全上限取較小者；安全上限只採官方文字可推得的值（如新生兒每天約 8–12 次哺餵，推得白天間隔上限約 3 小時），來源附在設定頁。
- 夜間與白天分開計算；0–6 個月夜間不排除提醒。
- 月齡常模的虛擬樣本固定為 5 筆，權重不隨時間衰減；介面顯示「依據 N 筆紀錄」。

### 6.2 提醒引發事件

- 提醒觸發後 15 分鐘內的事件標記為「提醒引發」，不納入上界計算。
- 餵食紀錄附「開始原因」，週報回饋「本週多數餵食是看到訊號後開始」。

### 6.3 不做的事

- 不做貝氏更新、不做存活模型、不做跨使用者模型。v0.3 的共軛模型保留在附錄作為第二階段選項。
- 不學習任何安全層數值。

### 6.4 評估

- 離線回放：以使用者本機紀錄計算「若當時提醒，與實際事件的誤差」，只在裝置上算，不上傳。
- 安全網觸發率、提醒被忽略率、使用者每週一題自評焦慮。

## 7. 技術架構與成本（一人開發）

### 7.1 架構

| 層級 | 決定 | 理由 |
|---|---|---|
| 前端 | Expo（React Native、TypeScript），dev client | 單一程式碼、EAS 免費額度、AI 工具支援度高 |
| 資料 | expo-sqlite，本地為唯一真相 | 無伺服器即無特種個資外洩面、無帳號系統、無月費 |
| 內容 | JSON 內容包隨 APP 打包；時程表 JSON 放靜態網頁空間可遠端更新 | 內容更新不需送審 |
| 通知 | expo-notifications 本地排程 | 無伺服器推播 |
| 備份 | 加密 JSON 匯出至使用者雲端硬碟 | 資料主權在使用者 |
| 分析 | 無 | 避免健康資料外流與隱私標示複雜度；只看商店後台 |
| 伺服器 | 無 | 第二階段同步功能再評估 |

**資料模型（18 歲架構）**：Child、Event（type、time、payload JSON）、Reminder（one-off、interval、schedule）、ScheduleItem（週期行程）、ContentCard（age band、style tags、evidence tag、source、checked_at）、ResourceTimeline（公費資源項目）。年齡段內容包以 age band 載入，第一階段只出 0–3。

### 7.2 通知可靠性

- iOS：64 筆本地通知上限，滾動排程；餵食與用藥提醒使用時效性層級，需在 App ID 啟用 `com.apple.developer.usernotifications.time-sensitive`。
- Android：使用 `SCHEDULE_EXACT_ALARM`（`USE_EXACT_ALARM` 只允許鬧鐘、日曆類）；Android 14 起新安裝預設拒絕，需以 expo-notifications 的 `requestExactAlarmPermissionsAsync` 引導；Android 13 起另需 `POST_NOTIFICATIONS`。
- APP 內「通知健康檢查」頁：通知權限、精準鬧鐘、省電白名單。
- 驗收：50 筆排程提醒在至少一支 iPhone、一支 Pixel 或三星、一支小米或 OPPO 上，觸發誤差中位數小於 1 分鐘。測試機以二手機取得。
